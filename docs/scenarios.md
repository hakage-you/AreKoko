| 試験 | E2E：`e2e/sc*.spec.ts`（`npm run test:e2e`）。結合：`tests/integration/scenarios.test.ts`（`npm test`） |

利用者が目的を果たすまでの流れを、手順と期待する結果で書く。**期待する結果は設計から決め、根拠の節を書く**（詳細設計(シナリオ) S9）。画面を見て決めてよいのは「どう操作するか」だけ。

- 手順の番号（`SC-01-3`）は、E2E と結合試験の手順の名前に使う。落ちたとき、どの手順が壊れたかが分かる。
- 根拠の書き方：数字だけは `docs/design.md` の節。「詳細」は `docs/detailed-design.md`、「詳細(段階N)」はその段階の詳細設計、V1・E2・R-A1 などは各詳細設計の決めごとの番号。
- すべてのシナリオで、最後に「保存されたファイルを読み直すと修復なしで読め、画面の文書と同じ」を確かめる（10章、詳細 4.6.1）。
