## 1. コア原則（Core Principles）

### 1.1 視覚シンボルと過剰装飾の排除
- **本質は「無用な過剰装飾の排除」**:
  - 画面を散らかしたり、注意を過剰に奪うような装飾目的のカラー絵文字（例: ヘッダーの 🔄 や、ボタンの 📍 など）はUIに混入させない。
  - ボタンやラベルにおける「文字 ＋ 装飾絵文字」の安易な併用は避ける（テキストのみ、またはテキスト記号で十分）。
- **シンプルな単色SVGアイコンの許容**:
  - 管理画面やツールバー等で使われるような「シンプルな1文字分のアウトライン／単色SVGアイコン（`currentColor` に追従）」は、明快な情報伝達として許容・推奨する。
- **サムネイル（KuukanThumb）とクウカンアイコン**:
  - カラー絵文字（`🏠` `🗄️` `📥`）は完全撤廃。
  - **未設定クウカン**: 洗練された単色アウトラインの未設定トレイSVGアイコンを表示。
  - **通常クウカン・収納クウカン**:
    - **図面プレビュー**: 図面がある場合の既定表示（SVG縮小ミニマップ）。
    - **クウカンアイコンのカスタマイズ**:
      - **組み込みSVGアイコン（8種類）**: 家・部屋（`home`）、棚・ラック（`shelf`）、箱・コンテナ（`box`）、引き出し（`drawer`）、クローゼット・収納（`closet`）、キッチン・台所（`kitchen`）、工具・作業場（`tool`）、本・書類（`book`）。単色アウトライン（24×24 viewBox, stroke-width=2, `currentColor`）でテーマや文字色に完全連動。
      - **一文字アイコンバッジ**: 任意の1文字を表示。未指定時はクウカン名の頭文字を自動適用。
      - **カラー設定**: 背景色（`bg`）および文字色（`fg`）は `#rrggbb` 形式のみ受け付け（原則7遵守）。
      - **図面との両立**: 図面があるクウカンでも任意設定が可能で、設定時は図面より優先される。いつでも「図面の表示に戻す」で図面描画へ復帰可能。
- **状態を繋ぐ機能的シンボルの例外**:
  - 「ずれ（`⚠ずれ`）」のように、閲覧画面（View）とサガシモノ画面（Search）などの複数画面間で、同一の注意状態を「補足引用的に結びつけて認知させる」ための機能的シンボルは、正当な例外として扱う。

### 1.2 モバイル・タッチ環境ファースト（No Hover Dependency）
- **ホバー依存の禁止**: タッチスクリーン端末にはマウスホバー操作が存在しない。そのため、「マウスホバー時のみ下線が出る・色が変わる」というホバー限定の装飾に依存してはならない。
- **静止状態でのアフォーダンス**:
  - タップできるリンクテキストは、初期表示の静止状態からアクセントカラー（`var(--accent)`）および下線（`text-decoration: underline; text-underline-offset: 4px;`）を表示し、ひと目でタップ可能と伝える。
- **タッチターゲットの確保**:
  - タップ可能なボタンや行、メニュートリガーは、最小高さ 40px（`--touch: 40px`）の領域を確保する。

### 1.3 テーマ完全両対応（Light / Dark Harmony）
- **セマンティック変数の活用**:
  - 必ず `src/ui/theme.css` で定義された CSS 変数（`--bg`, `--surface`, `--surface-2`, `--border`, `--text`, `--text-muted`, `--accent`, `--accent-soft`, `--danger`, `--danger-soft`, `--focus` 等）を使用する。
  - 枠線や透過色を定義する場合は、`color-mix(in srgb, var(--accent) 45%, transparent)` などを利用し、ライトテーマ（深緑 `#2f6f5e`）とダークテーマ（ミント `#6cc3a8`）の両方で背景と美しく調和し、十分なコントラスト比を維持する。

### 1.4 視覚ノイズと認知的負荷の最小化（Clarity over Ornamentation）
- **装飾よりも明瞭さを優先**: 意味を持たない装飾や、注意を過剰に奪う動的アニメーション・回転演出を避け、情報そのもの（クウカン・モノ）に自然と集中できるノイズレスな構成を徹底する。
- **画面要素の引き算と整理**:
  - 画面の主目的を考慮し、同一画面内で機能が重複する冗長なボタンや表示を排して選択肢を絞る。
- **状態伝達の静粛性と安心感**: システムの状態変化（保存、更新、エラーなど）は、ユーザーに無用な不安や警戒心を抱かせないよう、静的かつ端的に伝達する。

### 1.5 アクセシビリティとコントラスト基準（WCAG 2.1 AA）
- **相対輝度に基づく自動文字色選定**:
  - クウカンアイコンの背景色（`#rrggbb`）に対し、WCAG 2.1 の相対輝度（$L$）から白（`#ffffff`）と黒（`#0f172a`）のコントラスト比を数学的に算出し、高い方を自動選定する（`src/ui/color.ts` の `getContrastTextColor`）。
- **目標コントラスト比**:
  - 通常テキスト（18pt未満）: **4.5:1** 以上（WCAG AA）。
  - アイコン・大型太字テキスト（14pt太字以上）: **3.0:1** 以上（WCAG AA）。
- **テーマ精査結果**:
  - ライトテーマ: 本文テキスト（15.87:1）、控えめテキスト（5.70:1）、アクセントボタン（5.91:1）— 全て4.5:1以上クリア。
  - ダークテーマ: 本文テキスト（13.31:1）、控えめテキスト（6.04:1）、アクセントボタン（8.04:1）— 全て4.5:1以上クリア。
  - プリセットカラー全9色: 自動選定文字色により、全色で 4.3:1 以上のコントラスト比を達成（大半で4.5:1超）。

## 2. ボタン・アクションの視覚的ヒエラルキー

画面内のボタンが視覚的に競合し、ユーザーの迷いを生むことを防ぐため、以下の階層基準を適用する。

| 階層 / 種別 | スタイル仕様 | 適用基準 | 具体例 |
|---|---|---|---|
| **Primary<br>（強アクセント）** | `background: var(--accent);`<br>`color: var(--accent-text);`<br>`border: 1px solid var(--accent);` | 画面内で**唯一の決定打**となるアクション、または入力フォーム・ダイアログ展開時の**確定・送信アクション**。同一視界内で常時表示のPrimaryを複数並べて視覚を奪い合わせてはならない。 | ダイアログの「決定」「保存」、スタート画面の「新しく作る」、クウカン一覧の「+ クウカンを追加」、入力展開時の「作る」「追加」 |
| **Outline Accent<br>（同格アクセント）** | `background: var(--surface-2);`<br>`border: 1px solid color-mix(in srgb, var(--accent) 45%, transparent);`<br>`color: var(--accent);`<br>`font-weight: 600;`<br>*(ホバー時: `background: var(--accent-soft); border-color: var(--accent);`)* | 同一画面内で**重要なアクションが2つ共存**する場合に適用。ベタ塗り同士で喧嘩させず、同格の落ち着いたトーンで上品に目立たせる。 | クウカン閲覧画面の「モノを配置」と「＋モノを追加」 |
| **Neutral / Secondary<br>（通常ボタン）** | `background: var(--surface);`<br>`border: 1px solid var(--border);`<br>`color: var(--text);` | 一般的な操作、補助的な操作、キャンバス上のユーティリティ。 | 「全体を表示」「クウカン編集」ボタン等 |
| **Ghost<br>（軽量ボタン）** | `background: transparent;`<br>`border: none;`<br>`color: var(--text);` | 枠線を持たせない軽量なボタン、展開トグル、パンくずリンク。 | 「…」メニュートリガー、階層折りたたみ（▼/▶）、ヘルプミニボタン（？） |
| **Danger<br>（破壊的操作）** | `color: var(--danger);`<br>*(ホバー時: `background: var(--danger-soft);`)* | データの削除や破棄など、不可逆な変更を伴う操作。 | メニュー内の「削除」、ダイアログの破棄ボタン |

## 3. アクション配置と整理の指針（Action Placement）

### 3.1 主目的に応じたアクション配置と「畳む」判断
- **画面の主目的を最優先**:
  - 管理画面（ManageScreen）のように「管理・編集・削除」そのものが主目的である画面では、直接押せるボタンやアイコンを配置し、手数を最小化する。
  - サガシモノ画面（SearchScreen）の「クウカンで見る」のように、探した後の直後アクションも直接押せる形が望ましい。
- **主目的でない副次的アクションの煩雑化に対する対応**:
  - 画面の主目的ではないが必要なボタン（例: クウカン一覧における「かたちを編集」「複製」「名前の変更」「削除」など）が複数並び、画面が煩雑化したり行を圧迫する場合は、**「…」メニュー等に畳む（集約する）ことを検討する**。
  - これにより、日常の主動線（クウカンを開く）をクリアに保ち、画面幅の狭いモバイル環境でも崩れを防ぐ。

## 4. 画面別 UI 設計仕様

### 4.1 ヘッダー（Header）
- **構成**: `[ファイル名] [✓ 自動保存バッジ] [元に戻す] [やり直す] --- [画面切替タブ] --- [管理] [設定] [？ヘルプ]`
- **自動保存表示**:
  - `status: saved` 時は `[✓ 自動保存]` のピルバッジ（背景 `--surface-2`、文字 `--text-muted`、チェックマークはテキスト記号）。
  - 変更中や保存中は `[自動保存中...]` 等の落ち着いたテキスト表示。動的な回転アニメーションやカラー矢印は使わない。

### 4.2 クウカン一覧（KuukanScreen）
- **サムネイル（KuukanThumb）**: 図面がある場合は縮小表示、図面がない場合またはカスタマイズ時は「クウカンアイコン（一文字または組み込みSVGアイコン8種）」を表示。サムネイルのクリックまたは「…」メニューから「アイコンを変更」モーダルを開き、文字・アイコン種別・背景色・文字色をリアルタイムプレビューを見ながら選択可能。いつでも図面描画または初期設定へ戻すことができる。未設定クウカンは専用のトレイSVGアイコンを表示。
- **階層表示**: 親クウカンと収納クウカンのインデントとツリー構造（`▼`/`▶`/`└`）で親子関係を可視化。モバイル表示時はヘッダーでの収納合計件数表示を抑止し情報密度を最適化。
- **クウカン名リンク**: タッチ環境でもタップ可能と分かるよう、初期表示からアクセントカラー＋下線スタイルを適用。
- **アクションの集約**: 主目的である「クウカンを開く」動線を邪魔しないよう、副次的な「かたちを編集」「アイコンを変更」「複製」「名前変更」「削除」は右端の「…」メニューに集約。

### 4.3 クウカン閲覧画面（ViewScreen）
- **2大アクションの調和**:
  - 右上の「モノを配置」ボタンと、右ペインの「＋モノを追加」ボタンを、共に **Outline Accent** スタイルで統一。
- **かたちのないクウカン**:
  - 図面がないクウカン（Room A 等）では、キャンバス領域に「このクウカンにはまだかたちがありません」という静的メッセージカードを表示。絵文字や派手なアイコンは使わない。
- **エリア絞り込み**:
  - 間取り図のエリア（区画）をクリックすると、右のモノ一覧がそのエリアのモノに絞り込まれる。解除は「もう一度押すと元に戻ります」のガイダンスバーで明示。

### 4.4 クウカンエディタ画面（EditorScreen）
- **ツールバー**: 画面上部に操作ツール（四角、多角形、仕切り、目印）を配置。アクティブツールはアクセント背景。
- **操作の安全性**: 破綻を許さない設計原則に基づき、不正な形状や交差は描画時に即座にバリデーションし、安全にフィードバックする。
- **図面なし運用の文言統一**:
  - 新規作成・編集開始：「かたち（図面）を作る」
  - 図面の削除・リスト化：「かたちを削除（リストのみにする）」
  - 案内文：「かたち（図面）を作らずに確定すると、リストのみで管理するクウカンになります。図面は後からいつでも追加できます。」

### 4.5 サガシモノ画面（SearchScreen）
- **検索バー**: `Ctrl+K` または `/` で即座にフォーカス。
- **フィルタチップ**: カテゴリ・タグ・置き場などの条件チップを一覧表示。ワンタップで解除可能。
- **テーブル**: 仮想スクロールで大量のモノを高速描画。ずれのあるモノには機能的シンボルとして `⚠ずれ` を表示。

## 5. UI変更・機能追加時のセルフチェックリスト

- [ ] **過剰装飾チェック**: 無用な飾りとしてのカラー絵文字が混入していないか？（シンプルなSVGまたはテキスト記号か？）
- [ ] **タッチ・モバイルチェック**: ホバー時のみ現れる装飾に頼っていないか？（静止状態でもタップ可能と伝わるか？）
- [ ] **タッチ領域チェック**: ボタンや行の高さが最小 40px（`--touch: 40px`）以上あるか？
- [ ] **テーマ両対応チェック**: `theme.css` のCSS変数を活用し、特定テーマ前提のカラー値がハードコードされていないか？
- [ ] **コントラストチェック**: WCAG 2.1 AA基準を満たしているか？（通常テキスト4.5:1以上、太字/UIコンポーネント3:1以上。白黒文字の自動選定が適切に機能しているか？）
- [ ] **ボタンヒエラルキーチェック**: 同一視界内で常時露出するPrimaryボタン同士が視覚を奪い合っていないか？
- [ ] **アクション配置チェック**: 画面の主目的が優先されているか？ 主目的でない副次ボタンが煩雑化しているなら畳むことが検討されているか？
