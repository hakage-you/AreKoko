## 1. コア原則（Core Principles）

### 1.1 絵文字の完全禁止（Text Symbols & SVG Only）
- **カラー絵文字の禁止**: 📍, 📐, ⚠️, 🔄, 🔍 などのカラー絵文字は、OSやフォント環境によって色や形状、ニュアンスが激しく変化し、ダークテーマ・ライトテーマの両方でデザインの調和を損ねるため、UI全体で一切使用しない。
- **代替表現**:
  - 状態や操作は、日本語テキストまたは標準テキスト記号（`+`, `✕`, `…`, `▼`, `▶`, `✓`, `？` 等）で表現する。
  - アイコンが必要な場合は、`currentColor` に追従する単色のセマンティックなSVGアイコンを使用する。

### 1.2 モバイル・タッチ環境ファースト（No Hover Dependency）
- **ホバー依存の禁止**: タッチスクリーン端末にはマウスホバー操作が存在しない。そのため、「マウスを乗せたときだけ下線が出る・色が変わる」というホバー限定の装飾に依存してはならない。
- **静止状態でのアフォーダンス**:
  - タップできるリンクテキストは、初期表示の静止状態からアクセントカラー（`var(--accent)`）および下線（`text-decoration: underline; text-underline-offset: 4px;`）を常時表示し、ひと目でタップ可能と伝える。
- **タッチターゲットの確保**:
  - タップ可能なボタンや行、メニュートリガーは、最小高さ 40px（`--touch: 40px`）の領域を確保する。

### 1.3 テーマ完全両対応（Light / Dark Harmony）
- **ハードコード色の厳禁**: `rgba(52, 211, 153, 0.4)` のような特定テーマ前提のカラー値のハードコードは禁止する。
- **セマンティック変数の活用**:
  - 必ず `src/ui/theme.css` で定義された CSS 変数（`--bg`, `--surface`, `--surface-2`, `--border`, `--text`, `--text-muted`, `--accent`, `--accent-soft`, `--danger` 等）を使用する。
  - 枠線や透過色を定義する場合は、`color-mix(in srgb, var(--accent) 45%, transparent)` を利用することで、ライトテーマ（深緑 `#2f6f5e`）とダークテーマ（ミント `#6cc3a8`）の両方で背景と美しく調和し、十分なコントラスト比を維持する。

### 1.4 視覚ノイズと認知的負荷の最小化（Clarity over Ornamentation）
- **装飾よりも明瞭さを優先**: 意味を持たない装飾や、注意を過剰に奪う動的アニメーション・回転演出を避け、情報そのもの（クウカン・モノ）に自然と集中できるノイズレスな構成を徹底する。
- **画面要素の引き算**: 同一画面内で機能が重複する冗長なボタンや表示を排し、ユーザーが次に取るべき行動に迷わないよう、選択肢と視覚ノイズを最小限に抑える。
- **状態伝達の静粛性と安心感**: システムの状態変化（保存、更新、エラーなど）は、ユーザーに無用な不安や警戒心を抱かせないよう、静的かつ端的に伝達する。

## 2. ボタン・アクションの視覚的ヒエラルキー

画面内のボタンが視覚的に競合し、ユーザーの迷いを生むことを防ぐため、以下の階層基準を厳格に適用する。

| 階層 / 種別 | スタイル仕様 | 適用基準 | 具体例 |
|---|---|---|---|
| **Primary<br>（強アクセント）** | `background: var(--accent);`<br>`color: var(--accent-text);`<br>`border: 1px solid var(--accent);` | 画面内で**唯一の決定打**となる単一のアクション。画面内で2つ以上並べて視覚を奪い合わせてはならない。 | ダイアログの「決定」「保存」、スタート画面の「新しく作る」、クウカン一覧の「+ クウカンを追加」 |
| **Outline Accent<br>（同格アクセント）** | `background: var(--surface-2);`<br>`border: 1px solid color-mix(in srgb, var(--accent) 45%, transparent);`<br>`color: var(--accent);`<br>`font-weight: 600;`<br>*(ホバー時: `background: var(--accent-soft); border-color: var(--accent);`)* | 同一画面内で**重要なアクションが2つ共存**する場合に適用。ベタ塗り同士で喧嘩させず、同格の落ち着いたトーンで上品に目立たせる。 | クウカン閲覧画面の「モノを配置」と「＋モノを追加」 |
| **Neutral / Secondary<br>（通常ボタン）** | `background: var(--surface);`<br>`border: 1px solid var(--border);`<br>`color: var(--text);` | 一般的な操作、補助的な操作、キャンバス上のユーティリティ。 | 「全体を表示」「クウカン編集」ボタン等 |
| **Ghost<br>（軽量ボタン）** | `background: transparent;`<br>`border: none;`<br>`color: var(--text);` | 枠線を持たせない軽量なボタン、展開トグル、パンくずリンク。 | 「…」メニュートリガー、階層折りたたみ（▼/▶）、ヘルプミニボタン（？） |
| **Danger<br>（破壊的操作）** | `color: var(--danger);`<br>*(ホバー時: `background: var(--danger-soft);`)* | データの削除や破棄など、不可逆な変更を伴う操作。 | メニュー内の「削除」、ダイアログの破棄ボタン |

## 3. 情報設計（IA）と操作動線の分離

### 3.1 主動線と副動線の分離（一覧画面の標準設計）
ユーザーが日常的に行う操作（主動線）と、たまにしか行わない設定・管理操作（副動線）を行内で明確に分離する。

```
[サムネイル]  [クウカン名（常時リンク装飾）] [モノの数バッジ]  ----------->  […]
   │                      │                                               │
   └────── 行全体タップで閲覧画面を開く（主動線） ──────┘           タップでメニュー展開（副動線）
                                                                          ├ かたちを編集
                                                                          ├ 複製
                                                                          ├ 名前の変更
                                                                          └ 削除
```

- **主動線（クウカンを開いてモノを見る・追加する）**:
  - 行カード全体がタップ可能（`onclick`）。
  - クウカン名そのものが常時 `color: var(--accent)` ＋ 下線付きリンクスタイルで表示され、直感的に遷移できる。
- **副動線（かたちの編集・複製・名前変更・削除）**:
  - 各行の右端にある `…`（その他メニュー）に集約する。
  - 「かたちを編集」などの独立ボタンを行に露出させないことで、狭いスマホ幅でもタイトルやバッジが改行・圧迫されるのを防ぐ。

## 4. 画面別 UI 設計仕様

### 4.1 ヘッダー（Header）
- **構成**: `[ファイル名] [✓ 自動保存バッジ] [元に戻す] [やり直す] --- [画面切替タブ] --- [管理] [設定] [？ヘルプ]`
- **自動保存表示**:
  - `status: saved` 時は `[✓ 自動保存]` のピルバッジ（背景 `--surface-2`、枠線 `--border`、文字 `--text-muted`、チェックマークはテキスト記号）。
  - 変更中や保存中は `[自動保存中...]` 等の落ち着いたテキスト表示。動的な回転アニメーションやカラー矢印は使わない。

### 4.2 クウカン一覧（KuukanScreen）
- **階層表示**: 親クウカンと収納クウカンのインデントとツリー構造（`▼`/`▶`/`└`）で親子関係を可視化。
- **未設定カード**: 最上部に配置。薄い背景（`--surface-2`）と説明文で、置き場未定のモノの待避場所であることを明確にする。
- **アクション**: 各行は右端の `…` メニューのみ。右上の画面ヘッダーに唯一の Primary ボタン「+ クウカンを追加」を配置。

### 4.3 クウカン閲覧画面（ViewScreen）
- **2大アクションの調和**:
  - 右上の「モノを配置」ボタンと、右ペインの「＋モノを追加」ボタンを、共に **Outline Accent** スタイルで統一。
  - 画面内で競合せず、探す・配置する・追加する操作がスムーズに行える。
- **かたちのないクウカン**:
  - 図面がないクウカン（Room A 等）では、キャンバス領域に「このクウカンにはまだかたちがありません」という静的メッセージカードを表示し、右端に「編集」ボタンを配置。絵文字や派手なアイコンは使わない。
- **エリア絞り込み**:
  - 間取り図のエリア（区画）をクリックすると、右のモノ一覧がそのエリアのモノに絞り込まれる。解除は「もう一度押すと元に戻ります」のガイダンスバーで明示。

### 4.4 クウカンエディタ画面（EditorScreen）
- **ツールバー**: 画面上部に操作ツール（四角、多角形、仕切り、目印）を配置。アクティブツールはアクセント背景。
- **操作の安全性**: 破綻を許さない設計原則に基づき、不正な形状や交差は描画時に即座にバリデーションし、安全にフィードバックする。

### 4.5 サガシモノ画面（SearchScreen）
- **検索バー**: `Ctrl+K` または `/` で即座にフォーカス。
- **フィルタチップ**: カテゴリ・タグ・置き場などの条件チップを一覧表示。ワンタップで解除可能。
- **テーブル**: 仮想スクロールで大量のモノを高速描画。

## 5. 新規UI作成・変更時のセルフチェックリスト

UIコンポーネントを作成または変更する際は、必ず以下のチェックリストをすべて満たしていることを確認する：

- [ ] **絵文字チェック**: カラー絵文字（📍, 📐, ⚠️, 🔄, 🔍 等）が混入していないか？（テキスト記号またはSVGのみか？）
- [ ] **タッチ・モバイルチェック**: ホバー時のみ現れる装飾に頼っていないか？（静止状態でもタップ可能と伝わるか？）
- [ ] **タッチ領域チェック**: ボタンや行の高さが最小 40px（`--touch: 40px`）以上あるか？
- [ ] **テーマ両対応チェック**: `theme.css` のCSS変数を使用しているか？特定テーマ前提のRGB値がハードコードされていないか？
- [ ] **ライトモードコントラストチェック**: ライトテーマ（背景 `#f7f6f3`、`#ffffff`）で文字や枠線が視認できるか？
- [ ] **ダークモードコントラストチェック**: ダークテーマ（背景 `#181715`、`#22201d`）で文字や枠線が眩しすぎず視認できるか？
- [ ] **ヒエラルキーチェック**: 画面内に Primary（ベタ塗り）ボタンが複数乱立して視覚を奪い合っていないか？
- [ ] **情報設計チェック**: 日常操作（主動線）と管理・設定操作（副動線）が適切に分離されているか？
