## 1. AI向けの説明ページ（`public/ai.md`）

書く内容（設計 6.8）：

1. このページの目的と、編集の前にファイルの複製を取ること。破綻はサポートしないこと。
2. 文書の形（6.4）。所属の層だけを扱えばよいこと。
3. AIに任せてよい範囲：モノ・カテゴリ・タグの追加、既存の置き場へのモノの配置（置き場の変更）、描画なしのクウカンの作成。
4. 非推奨：描画の層（`drawing` の中）には触れない。アプリで描くことを勧める。
5. ID の決まり：新しい要素には `new:` で始まる仮ID。既存の ID は書き換えない。未設定は Nil UUID。
6. 各一覧の項目（必須・任意・既定）と、守る条件（6.5 の 1〜8 を、AI が守るべき形に言い直す）。
7. 例：前と後の文書（モノ2つ・新しいカテゴリ・新しいタグ・既存のエリアへの配置・描画なしのクウカンの作成）。
8. 読み込むとき何が起きるか（仮IDの付け替えを一覧で見せ、承認で読み込む）。

## 2. 試験（`tests/integration/ai-page.test.ts`）

- `ai.md` の ```` ```json ```` の塊のうち、`<!-- example:before -->` と `<!-- example:after -->` の直後のものを取り出す。
- before は `analyzeDocument` で ok（修復なし）。
- after は `repair` で、修復の一覧が仮IDの付け替えだけ。承認後の文書が `validateDocument` を通り、例で足したモノが例で決めた置き場・カテゴリ・タグを持つ。before にあったものは変わらない。
- `llms.txt` が `ai.md` と `schema.json` を指していて、そのファイルが `public/` にある。
