# アレココ 結合試験の観点（段階1〜4）

| 項目 | 内容 |
|---|---|
| 作成日 | 2026-10-08 |
| 目的 | 単体テストでは見えない「部品どうしをつないだときに、設計の意図どおりに動くか」を確かめる |
| 対象 | `AppStore`（画面の状態）＋ `DocumentSession`（保存）＋ 中核（読み込み・検査・操作）＋ 検索。画面（Svelte）は除く（画面での確認は別に行う） |
| 置き場所 | `tests/integration/*.test.ts` |

結合試験は、利用者の操作の流れを `AppStore` の公開の操作だけで再現し、**最後に保存されたファイルの中身**（偽の保存先が持つ JSON 文字列）と画面の状態を確かめる。中核の関数を直接呼んで文書を作るのは、試験の前提（壊れたファイルなど）を用意するときだけにする。

すべての試験で、次の共通の確認をする（`expectHealthy`）：

- 保存されたファイルの中身を `analyzeDocument` にかけると `ok`（修復が要らない）。
- 保存されたファイルは改行・空白なし（設計 6.1）。
- 画面の状態の `doc` が `validateDocument` を通る。

## 1. 段階の終わりの目安（設計 13章）

| # | 観点 | 設計 | 確かめ方 |
|---|---|---|---|
| S1 | 壊れた文書・仮IDを含む文書を読み込み、修復案どおりに直せる | 13章 段階1、6.7 | 置き場の参照先なし・カテゴリなし・タグなし・仮ID（`new:`）・UUID v4 のIDを含むファイルを開く → 修復の確認（一覧の件数と内容）→ 承認 → 1秒後に保存されたファイルを読み直すと `ok`、仮IDは v7 に、参照も同じIDに、移したものに修復メモ、仮IDの付け替えにはメモなし |
| S2 | 修復を断れば何も変わらない | 6.7 | 同じファイルで「読み込まない」→ 最初の画面のまま、ファイルは書かれない |
| S3 | 輪のあるファイルは断る | 6.7 | 入れ子の輪 → dialog 'refused'、理由に名前が並ぶ、ファイルは書かれない |
| S4 | 2つのタブで同じファイルを開いても、変更が黙って消えない | 13章 段階3、10章 | 同じ偽の保存先を2つの AppStore で開く。A で変更 → 保存。B で変更 → B は conflict（書かない）、A の内容が残っている。B が「読み込み直す」→ A の変更が見える。B が「それでも上書きする」→ B の内容になる（利用者が選んだとき） |
| S5 | 描画なしで、登録・検索・移動が一通りできる | 13章 段階4 | 新しく作る → クウカンを作る → モノを追加（置き場あり／なし）→ 収納にする → 収納の中へ移す → 検索（文字・置き場〔中の収納まで〕・カテゴリ・タグ）→ 閉じて開き直すと同じ |

## 2. 統一規則（設計 7.8）

各場面で、移ったモノが `highlights` に入ること、ファイルに書かれた行き先、`moved` の外には何も動いていないこと、修復メモが付かないこと（6.7「アプリ内の操作では付けない」）を確かめる。

| # | 場面 | 行き先 |
|---|---|---|
| U1 | 仕切りを消して、エリアがなくなった | 親のエリア（なければクウカンそのもの）。同じクウカンの中なので描画は残る |
| U2 | N等分の兄弟の間の仕切りを消した | 親。合わさった範囲に空の新しいエリア |
| U3 | 収納のモノを削除した | 収納があった置き場。中の収納は中身ごと移る |
| U4 | 収納設定を削除した | 収納があった置き場。収納だったモノのIDは変わらない（7.5） |
| U5 | どこにも置かれていないクウカンを消した | 未設定。中の収納は中身ごと |
| U6 | 移る前に影響を見せる | `plan〜` の内容が、実行後の実際の移動と一致する |

（U1・U2 は描画が要るので、中核の操作で描画つきのクウカンを用意してから開く。U3〜U6 は画面の操作の流れで行う。）

## 3. データと操作の規則

| # | 観点 | 設計 | 確かめ方 |
|---|---|---|---|
| D1 | アプリが知らない項目は、編集して保存しても消えない | 6.1 | 文書・モノ・クウカンに未知の項目を入れたファイル → 開いて、そのモノを編集・移動 → 保存されたファイルに未知の項目が残る |
| D2 | 計算で出せるデータは保存しない | 原則6 | 保存されたファイルに、経路・件数・作成日時（createdAt など）の項目がない。作成日時は ID から読める |
| D3 | 処理はID、名前は表示専用（同じ名前があってよい） | 原則5 | 同じ名前のタグ・カテゴリ・クウカンを作って、それぞれ別に操作できる |
| D4 | カテゴリを消すと、中のモノと子カテゴリが親へ | 7.6 | 3段のカテゴリの真ん中を消す |
| D5 | タグを消すと、全部の参照が消える | 7.6 | 複数のモノに付いたタグ |
| D6 | 収納を自分の中に置けない | 7.5、8.6 | 収納の中へ自分を移す → toast（error）、文書は変わらない。`placeCandidates` に自分の中が出ない |
| D7 | 置き場を別のクウカンへ変えたら、描画は外れる | 7.7 | 描画つきのモノを別のクウカンへ |
| D8 | 修復メモは消すことだけできる | 6.7 | 修復で付いたメモを消す → 保存されたファイルから消える |
| D9 | 数量の「なし」と「0」は違う | 7.4 | 数量を消すと項目ごとなくなる。0 は 0 として残る |

## 4. 保存と安全（設計 10章）

| # | 観点 | 確かめ方 |
|---|---|---|
| P1 | 自動保存は約1秒待ってまとめて1回 | 0.9秒以内に3回操作 → 書き込み0回、最後の操作から1秒で1回 |
| P2 | タブを隠す・閉じるときは待たずに書く | `flush()` で即時に書く |
| P3 | 自動保存オフでは書かない（flush でも） | 設定をオフ → 操作 → 時間を進めても、flush しても書かない。保存ボタン（`save()`）で書く。設定は保存される |
| P4 | 書く前に必ず検査し、問題があれば書かない | 不変条件を壊す操作を（試験のために）通す → 'invalid'、ファイルは前のまま |
| P5 | 閉じるときの警告 | 自動保存オフで変更 → closeDocument → confirm。自動保存の待ちの途中 → 書いてから閉じる（confirm なし） |
| P6 | 元に戻すは直近50回、画面を切り替えたら消える、まとめ方の切り替えでは消えない、戻した後の新しい操作でやり直すが消える | 51回操作 → 50回戻せる。setScreen で canUndo false。setGrouping では残る |
| P7 | ハイライトはその場限りで、文書には残さない | 統一規則で移った後、保存されたファイルにハイライトの印がない。次の操作で消える |
| P8 | 新しく作るとすぐ保存先に書かれる（D6） | newDocument → ファイルの中身がすぐ正しい空の文書（0バイトでない） |
| P9 | ブラウザに残すのは設定だけ | 設定の保存先に書かれるのは `{ autosave }` だけ |

| # | 観点 | 確かめ方 |
|---|---|---|

## 6. 結合試験のレビューで強めたこと（2026-10-08）

ワーカーが書いた結合試験を、観点表の意図と照らして読み、次を足した。

- 共通の確認に「『保存済み』と出ているとき、画面の文書とファイルの中身が一致する」を追加（表示が嘘をつかない）。
- 統一規則のすべての場面で「moved に入ったモノだけが動き、ほかは動いていない」を確かめる（`expectOnlyMoved`）。
- U1b（入れ子の仕切りを消すと、中身は親のエリアへ）、U6b（線を消す・収納のモノを消すときも plan〜 が実際と一致）を追加。
- S1：外したり移したりした3つそれぞれに修復メモがあること、日時が読み込みの時刻であること。
- D2：決め打ちの項目名の不在ではなく、保存される項目が設計の項目の範囲に収まることを確かめる。
- D7：同じクウカンの中の移動では描画が残り、別のクウカンへの移動で外れる、の両方。
- P4：不具合で書けなくなっても、元に戻せば正常に書ける（閉じ込められない）。

## 段階6：クウカンビュー（`tests/integration/view.test.ts`、`tests/app/store.view.test.ts`）

観点は `docs/detailed-design-view.md` 7章（V-1、V-S、V-A、V-C、V-O、V-N、V-Q、V-F、V-M、V-D）。ユーザーの指示（クウカンがメインの画面、モノの追加はクウカンから、サガシモノに追加ボタンを置かない）を V-1・V-A で確かめる。
