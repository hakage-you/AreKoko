# アレココの文書をAIが編集するための説明

アレココは、家の中の「どこに何があるか」を、自分で描いた間取りとリストで管理するアプリです。データは1つの JSON ファイル（以下「文書」）に入っています。このページは、利用者に頼まれた AI が文書を直接編集して、モノなどを追加するための説明です。

- 形式の定義（JSON Schema）：[schema.json](./schema.json)
- このページは、アプリと同じ場所にある `ai.md` です。`llms.txt` からも辿れます。

## はじめに（利用者へ・AIへ）

- **編集する前に、必ずファイルの複製を取ってください。** アプリは読み込むときに文書を検査し、直せるものは直し方を一覧で見せますが、AI の編集で壊れた文書の手当てはサポートしていません。
- 文書を受け取ったら、まず全体を読み、既存の ID と名前を把握してから編集してください。
- 編集した文書は、利用者がアプリの「ファイルを開く」で読み込みます。

## AI に任せてよいこと

| してよいこと | 書き方 |
|---|---|
| モノを追加する | `membership.items` に足す |
| モノの置き場を変える（既存の置き場へ） | そのモノの `place` を書き換える |
| カテゴリを追加する | `membership.categories` に足す |
| タグを追加する | `membership.tags` に足す |
| 描画なしのクウカンを作る（物置・倉庫など） | `membership.kuukans` に足す（`owner: null`） |
| モノの名前・概要・数量・カテゴリ・タグを直す | そのモノの項目を書き換える |

## してはいけないこと

- **`drawing`（描画の層）には触れない。** 間取りの外形・仕切り・マーカー・モノの描画は、アプリの画面で描いてください。触れると、そのクウカンの図が読み込み時に外れることがあります。
- **エリア（`membership.areas`）を足したり消したりしない。** エリアは、アプリで間取りに仕切りを入れたときにだけできます。
- **既存の ID を書き換えない。** 参照が切れます。
- 収納（中にクウカンを持つモノ）を作らない・外さない。アプリの「収納として設定する」を使ってください。
- 要素を消すのは、利用者にはっきり頼まれたときだけにしてください。消すときは、それを参照しているもの（モノの `place`・`category`・`tags`、カテゴリの `parent`）も直してください。

## 文書の形

```text
{
  "app": "arekoko",            … 常にこの値
  "schemaVersion": 1,          … 常にこの値
  "membership": {              … 所属の層（AI が編集するのはここだけ）
    "kuukans": [...],          … クウカン（部屋・物置、収納の中）
    "areas": [...],            … エリア（クウカンを仕切った区画。AI は足さない）
    "items": [...],            … モノ
    "categories": [...],       … カテゴリ（木）
    "tags": [...]              … タグ
  },
  "drawing": {...}             … 描画の層（触れない）
}
```

アプリが知らない項目は、保存しても消えずに残ります。ファイルは改行なしの1行で保存されていますが、読み書きの際に整形してもかまいません。

### クウカン（`membership.kuukans[]`）

| 項目 | 必須 | 内容 |
|---|---|---|
| `id` | ○ | ID（下の「ID の決まり」） |
| `name` | 部屋・物置では入れる | 名前。収納の中のクウカンは名前を持たない（持ち主のモノの名前で表示される） |
| `owner` | | `null`（どこにも置かれていない、部屋や物置など）か、収納であるモノの ID。**AI が作るときは常に `null`** |
| `areaLabel` | | エリアの呼び名（「床」「段」「引き出し」など）。省略すると「エリア」 |

ID が `00000000-0000-0000-0000-000000000000` のクウカンは「未設定」です。置き場が決まっていないモノはここに置きます。名前を変えたり消したりしないでください。

### エリア（`membership.areas[]`）

読むだけにしてください。`kuukan` は属するクウカン、`parent` は親のエリア（`null` ならクウカンの直下）、`name` は表示名（「段1」など）です。親を持つエリアは「子のどれかにある」ことを表す置き場で、モノを置いてもかまいません。

### モノ（`membership.items[]`）

| 項目 | 必須 | 内容 |
|---|---|---|
| `id` | ○ | ID |
| `name` | ○ | 名前（例：「単3電池」） |
| `place` | ○ | 置き場。クウカンの ID（クウカンそのもの）か、エリアの ID。決まっていなければ未設定 `00000000-0000-0000-0000-000000000000` |
| `category` | | カテゴリの ID。省略か `null` で未分類 |
| `tags` | | タグの ID の配列。同じタグを2回入れない |
| `summary` | | 概要（自由な文） |
| `qty` | | 数量（0 以上の整数）。**分からなければ省略**（1 と書かない） |
| `updatedAt` | | アプリが書く。AI は書かなくてよい（既存のモノを直したら、消すか、今の日時を ISO 8601 で入れる） |

### カテゴリ（`membership.categories[]`）・タグ（`membership.tags[]`）

| 項目 | 必須 | 内容 |
|---|---|---|
| `id` | ○ | ID |
| `name` | ○ | 名前 |
| `parent` | | カテゴリだけ。親のカテゴリの ID か `null`（いちばん上） |
| `color` | | 画面で付ける色。`#rrggbb` の形（例：`#0284c7`）。省略すると既定の色。ほかの形の値は使われない |

同じ名前のカテゴリやタグがすでにあれば、新しく作らずにそれを使ってください。

### `notices`（修復メモ）

要素に `notices` があれば、アプリが読み込み時の修復で書いた記録です。書き換えたり足したりしないでください。

## ID の決まり

- 既存の要素の ID は UUID v7（小文字）です。書き換えないでください。
- **新しく足す要素には、`new:` で始まる仮 ID を付けてください。** 例：`"new:単3電池"`、`"new:cat-電池"`。
  - 文書の中で重複しないこと（既存の ID とも、ほかの仮 ID とも）。
  - 参照するときも、その仮 ID をそのまま書きます（例：モノの `"category": "new:cat-電池"`）。
- アプリは読み込むときに、仮 ID を本物の UUID v7 に付け替え、参照もまとめて書き換えます。付け替えは一覧で利用者に見せ、承認を得てから行います。

## 守る条件

アプリは常に次の条件を満たす文書を扱います。編集後も満たしてください。満たさないと、読み込み時に修復の一覧が出るか、読み込みを断られます。

1. ID は文書全体で重複しない（クウカン・エリア・モノ・カテゴリ・タグ、描画のマーカーを通して）。
2. 未設定のクウカン（`00000000-0000-0000-0000-000000000000`）がある。
3. モノの `place` は、存在するクウカンかエリアの ID。
4. モノの `category` は、存在するカテゴリの ID か `null`。`tags` の各 ID は存在し、重複しない。
5. カテゴリの `parent` は、存在するカテゴリか `null`。親をたどって元に戻る輪を作らない。
6. エリアは足さない・変えない（エリアの条件はアプリが守る）。
7. クウカンの `owner` は `null` のまま（収納はアプリで作る）。
8. 収納の中に、その収納自身を入れない（モノ A が持つクウカンの中に、A を置かない。入れ子をたどって元に戻る輪を作らない）。**輪になっている文書は、アプリが読み込みを断ります。**

## 置き場の探し方（文書の読み方）

- 「棚の段1」のような置き場は、`areas` から `name` が「段1」で、`kuukan` が名前「棚」のクウカンの ID であるものを探します。
- 部屋の中の家具（棚など）が収納になっていることがあります。そのときは、モノ「棚A1」を `owner` に持つクウカンがあり、その中のエリアが「段1」などです。
- 見つからない、または迷うときは、未設定に置いて、利用者にアプリで置き場を決めてもらってください。
